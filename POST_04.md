Topic 4 --- POST API in Playwright
================================

1\. What is POST?
-----------------

**POST is commonly used to send data to the server and create a new resource.**

Example:

```
POST /posts
```

We send data:

```
{
  "title": "Playwright API Test",
  "body": "Learning POST API",
  "userId": 1
}
```

* * * * *

2\. How to send POST request in Playwright?
-------------------------------------------

Use:

```
request.post()
```

Example:

```
const response = await request.post('/posts', {
    data: {
        title: 'Playwright API Test',
        body: 'Learning POST API',
        userId: 1
    }
});
```

### Important

`data` contains the **request body/payload** that we send to the API.

* * * * *

3\. Basic POST API flow
-----------------------

```
request.post()
      ↓
URL + request data
      ↓
Server
      ↓
Response
      ↓
Validate status
      ↓
Read response body
      ↓
Validate response fields
```

* * * * *

4\. Request body / payload
--------------------------

The data sent to the API is called the **request body** or **payload**.

Example:

```
data: {
    title: 'Test',
    body: 'Learning API',
    userId: 1
}
```

So remember:

> **`data` → request body/payload**

* * * * *

5\. Status code
---------------

A successful POST that creates a resource commonly returns:

```
201 Created
```

Example:

```
expect(response.status()).toBe(201);
```

⚠️ Don't say **"POST always returns 201"** in an interview.

Better:

> A successful resource-creation POST commonly returns 201, depending on the API contract.

* * * * *

6\. Reading POST response
-------------------------

After receiving the response:

```
const responseBody = await response.json();
```

Now we can access individual fields:

```
responseBody.title
responseBody.body
responseBody.userId
responseBody.id
```

* * * * *

7\. Request data vs response data
---------------------------------

This is **VVIP**.

We send:

```
data: {
    title: 'Test',
    body: 'Learning API',
    userId: 1
}
```

The server may return:

```
{
    "title": "Test",
    "body": "Learning API",
    "userId": 1,
    "id": 101
}
```

Notice:

```
Request:
title
body
userId

Response:
title
body
userId
id
```

The `id` can be **generated by the server**.

* * * * *

8\. `userId` vs `id`
--------------------

Don't confuse these.

```
userId
   ↓
Identifies the user associated with the post

id
   ↓
Identifies the post/resource itself
```

Example:

```
{
    "userId": 1,
    "id": 101
}
```

Means:

> Post 101 belongs to user 1.

* * * * *

9\. Validating response
-----------------------

We can validate the returned data:

```
expect(responseBody.title).toBe('Playwright API Test');

expect(responseBody.body).toBe('Learning POST API');

expect(responseBody.userId).toBe(1);
```

If we only care that an ID was generated:

```
expect(responseBody.id).toBeTruthy();
```

### `toBeTruthy()`

Means the value should be truthy---not `false`, `0`, `null`, `undefined`, or an empty string.

* * * * *

10\. Complete POST example
==========================

This is the main code you should remember:

```
import { test, expect } from '@playwright/test';

test('Create post', async ({ request }) => {

    const response = await request.post(
        'https://jsonplaceholder.typicode.com/posts',
        {
            data: {
                title: 'Playwright API Test',
                body: 'Learning POST API',
                userId: 1
            }
        }
    );

    expect(response.status()).toBe(201);

    const responseBody = await response.json();

    expect(responseBody.title).toBe('Playwright API Test');
    expect(responseBody.body).toBe('Learning POST API');
    expect(responseBody.userId).toBe(1);
    expect(responseBody.id).toBeTruthy();
});
```
